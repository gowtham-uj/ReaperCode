# Red-team audit, September 2026

The browser layer was attacked by subagents running DeepSeek flash through the
dynamic workflow tool. Each finding below was reproduced by executing the code,
not by reading it, and each fix carries a test that fails without it.

Two kinds of finding appear here. The first kind is a leak or a wrong answer in
the runtime. The second is a written claim the code does not honour, which is the
more expensive kind: the model reads the claim and builds on it, and the failure
surfaces three steps later somewhere unrelated.

## What was fixed

### Sandbox escapes (critical)

A browser program runs with no browser objects of its own. It holds proxies, and
the host replays every call against the thread's real page. Isolation therefore
depends on every object a program can reach being a scoped proxy, and the
red-team pass found four raw objects and one route that bypasses names entirely.

| door | how it was reached | fix |
| --- | --- | --- |
| `context.newPage()` | not intercepted in `scopeContext`; returned a raw Page | wrapped, so the new page is scoped |
| `browser.newBrowserCDPSession()` | absent from `scopeBrowser`'s refusal list; answered `Target.getTargets` with every tab | refused |
| `browser.runtime` | `BrowserFacade`'s TypeScript `private` field is a runtime property | `#runtime` |
| `browser.initial` | same, and it held the raw unscoped Page | `#initial`, plus a name allowlist over the whole facade |
| `page.constructor` / `Object.getPrototypeOf(page)` | not a name at all: the real prototype method runs with the proxy as `this` | the three prototype names throw; scoped objects report `Object.prototype` |
| `expectPopup` | interned the raw Playwright Page the host got from `waitForEvent("popup")` | interned through the scoping door |

The prototype route is the one worth reading the source for. A `get` trap that
special-cases a handful of names and forwards the rest cannot close it by adding
another name, because `constructor` is every name at once. It is refused in the
trap, and `Object.getPrototypeOf` (a different trap) is answered with
`Object.prototype`.

### HTTP surface (critical)

`/api/file?path=.reaper/browser/<id>.json` served a live cookie jar in cleartext.
`.reaper` was not in the file routes' ignore list, and `resolveInsideRoot` did not
exclude it, so it was readable by name and enumerable by listing. The route also
served the session journal and spilled pastes, both of which have a properly
scoped route of their own, so the file route was a bypass around it.

Two more on the same surface:

- `/preview/<port>/` serves an arbitrary dev server's document on the gateway's
  own origin, and a same-origin `fetch("/api/file?...")` from it carries no
  `Origin` header, so the origin rule passed it. A dev server the agent started
  could read the cookie jar. Requests to `/api/*` whose referer is a preview
  document are now refused.
- `writeWorkspaceUpload` did not call `assertNotCodeLoadingPath`, which every tool
  write calls. `POST /api/upload?path=.reaper/hooks/evil.json` landed bytes the
  tool path would have refused.

### Resource leaks

- `CdpSocket.open`'s timeout path left the socket in the event loop; a suite that
  passed every assertion never exited.
- `HealthMonitor` kept a strong `Map` entry and five listeners per page forever.
  Closed pages are now dropped.
- `BrowserControlRegistry.forget` had no caller, so a deleted thread's lease
  survived its id.
- `beginHumanControl` assigned its detachers to one field, so a second takeover
  leaked the first pair for the life of the runtime.

### Wrong answers

- `ArtifactManager.newestUnclaimed` took the last file in the vault with no
  staleness filter, so a `waitForEvent("download")` that rejected answered with
  whatever the thread had downloaded last, and the ledger recorded it against the
  action. A file counts only if it landed after the arm.
- The verifier's `matchPattern` is a substring test, so `pattern: ""` matched
  everything and a run that did nothing verified. Empty patterns are refused.
- Nothing ever wrote the `verified` subtask status, so a `subtask` requirement
  answered "not verified" forever. The runtime now promotes a `done` subtask when
  every concrete requirement passes.
- `state.subtask(title, status, requires)` dropped `requires`, so a subtask with
  prerequisites appeared in `READY NOW` before them.
- The mission state's moving-subtask list had no bound and is re-sent every turn.

### Dead wiring

`kit.forgetPage` existed, was correct, and was called by nothing. It is now
called from the close listener. `indexedDbRestoreNote` was written and read by
nothing; it now has a taker and the tool reads it. `watchDownloads` had no
idempotence guard, so a page reached by two call sites got two listeners and one
download produced two vault files.

## Documentation that did not match the code

These are recorded because they mislead the model rather than the user.

- `README.md` claimed a "desktop-control tool" that does not exist in the
  registry. Corrected.
- `SKILL.md` documents `expect(locator).toBeVisible()`, which was `undefined`
  inside a sandboxed program, and `wait-policy.ts` told the model to write it.
  The sandbox now binds `expect` with the four assertions the skill names, and a
  failing assertion throws rather than returning, because `await expect(x)` to a
  comment discards the value.
- The cut notice told the model to use `view({ selector })` and `view({ depth })`.
  Both reached the host as one options object the runtime read as a *page*, so the
  read fell back to the whole page: a program following the tool's own remedy paid
  for the full page and could not tell. Both now work, `depth` on the whole-page
  path as well as the scoped one.
- The observation helpers revived handle markers but not value markers, so
  `expect(page).toHaveURL(/example\.com/)` compared the URL against the string
  `"[object Object]"`. One entry point now revives both, so a helper and a method
  call cannot disagree about what a marker means.
- `tools.md` is generated and was stale: it lists `browser_control` and
  `skim_file` where the registry has `browser_use` and no `skim_file`. Regenerated,
  and a test now asserts the committed file matches the registry so it cannot go
  stale again.

## What the second pass found in the first pass

Two adversarial verifiers checked the fixes above by reverting each one and
watching a test fail. Three of their findings are worth recording, because the
failure mode is the same one this document is about: a fix that reads as done.

- A test added for the web-search engine bug passed against the pre-fix code. Its
  assertion was `["duckduckgo","mimo","serper"].includes(result.engine)`, and the
  pre-fix code returned a hardcoded `"mimo"`, which is in that list. A test that
  passes both ways proves nothing. Rewritten to pin the property that actually
  broke.
- A docstring in the same test described a schema that never existed (`brave` in
  the accepted enum). Corrected to say what was true.
- The download floor for a rebuilt runtime used process start, which does not
  bound the case it was written for: the vault outlives the runtime object and
  `downloadedFiles` does not, so a runtime rebuilt after the idle reaper holds an
  empty list over a vault full of the thread's earlier downloads. The floor is now
  the runtime's own construction time.
- `expect`'s budget was read from `options.timeout` only, so the equally natural
  `{ timeoutMs: 250 }` was silently ignored and the program took the 5-second
  default. Found by the verifier reading its own test: the test passed a
  `timeoutMs` that was never used.
- The refusal message `expect.ts` documented for an unknown assertion was
  unreachable: the sandbox answers the property, so `expect(page).toHaveCount(3)`
  threw a JavaScript `TypeError` naming the binding rather than the browser
  surface. The sandbox now answers through a proxy that refuses with the list,
  and a test reads the sandbox source and asserts its list matches the host's
  set, so the two cannot drift.

## What the sandbox still does not claim

This is JavaScript in one process. The prototype route is closed and every
documented accessor is scoped, but a script that goes looking is not stopped by a
same-process guard in general. One browser process per thread is the fix that
would close it, and nobody has priced it. The README states this rather than
implying more.
